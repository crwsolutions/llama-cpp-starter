TECHNISCHE NOTITIES — DATA BRONNEN PER CARD
--------------------------------------------------------------------------------

Deze notities documenteren waar de data voor de diverse kaarten/velden op
scherm 1 vandaan komt.

### 1. ModelStatus (bv. "Loaded Qwen3.6...")

Bron: Lokale application state (ModelRuntimeStatusTracker)

- Wordt bijgehouden door de app zelf, NIET van de server gehaald
- Drie staten: Loading, Loaded, Fallback
- De "Loading Time" wordt berekend vanaf een interne timer (_loadingStartedAt)

### 2. Hardware (GPU info)

Bron: Lokale systeem probe (GpuStatusProbeService + GpuSummaryService),
ALLEEN nvidia-smi (gebruikersbeslissing 2026-08-19; geen AMD/Intel/CPU-probes)

- Gebruikt systeemcommando's (niet de llama-server gateway!)
- nvidia-smi --query-compute-apps=gpu_uuid,pid → uuid's van het
  llama-server-proces; daarna nvidia-smi --query-gpu=... --format=csv,noheader,nounits
  voor die uuid's; bij falen/leeg → volledige --query-gpu-lijst
- Geen NVIDIA-GPU of nvidia-smi afwezig → "Unavailable"
- Resultaat wordt gecached in GpuSummaryCache (10 s per sessie-key)

### 3. Slots (bv. "Active 0/1, Queued 0, Busy/decode 1,0")

Bron: llama-server /slots endpoint (via RuntimeMetricPollerService)

- Pollt http://localhost:{port}/slots van de draaiende llama-server
  (elke 2 s; /slots is standaard enabled)
- Parse de JSON response naar RuntimeSlotSnapshot
- Toont per-slot status en verwerkingsinformatie

### 4. Tokens (bv. "Generated 102.0 t/s, Prompt 34.2 t/s")

Bron: llama-server /metrics endpoint (via RuntimeMetricPollerService)

- Pollt http://localhost:{port}/metrics van de draaiende llama-server
  (alleen wanneer het geladen profiel "Metrics endpoint" heeft aangevinkt,
  anders /metrics geeft 501 "not enabled" → kaarten vallen terug op
  /slots-data/last-known)
- Parse Prometheus formaat data naar PrometheusSample
- RuntimeMetricSummaryTracker berekent rates, totals, en deltas
- Genereert rates op twee manieren:
  - Wall-clock rate: tokens / verstreken tijd
  - Seconds-based rate: tokens / actieve generatie-seconden
    (voorkomt dilutie tijdens idle gaps)

### 5. MTP-tokens (bv. "Inactive")

Bron: llama-server /metrics endpoint (dezelfde als Tokens)

- Specifiek voor MTP (Multi-Tensor Parallel) speculative decoding
- Alleen actief wanneer het geladen profiel SpecType ingesteld is op
  draft-* of mtp; anders "Inactive"

### 6. KV-cache (bv. "Used 2.146 t | 1,6%, Capacity 131.072 t")

Bron: llama-server /metrics endpoint (dezelfde als Tokens)

- Haalt kv.cache.usage, kv.cache.tokens, context.size uit de metrics
- Capacity komt van de slot data of de profiel-CtxSize

SCHERM 3: RUNTIMES - RUNTIME SELECTEREN
================================================================================

Beschrijving:
De "Runtimes" pagina. Hier beheer je lokale llama.cpp builds (runtimes) die
kunnen worden gebruikt om modellen te draaien. Je kiest een map, scant op
geïnstalleerde builds, en kunt runs toevoegen of verwijderen.

LAYOUT:
- Linker sidebar: zelfde 4 items, "Runtimes" nu geselecteerd (met code-icoon)

- Bovenste balk:
  - Twee tabs/knoppen: "Map kiezen" (geselecteerd) en "Run timemap"
  - Pad label: "E:\llama.cpp\llama-local-build"

- Hoofdinhoud:
  - Titel: "Geïnstalleerde lokale builds"
  - Tabel met kolommen:
    - Naam
    - Backend
    - Status
    - Locatie
    - Actie
  - Voorbeelddata (1 rij):
    - Naam: "llama.cpp llama-local-build Native Cuda"
    - Backend: "Cuda"
    - Status: "Built Native"
    - Locatie: "E:\llama.cpp\llama-local-build\llama-server.exe"
    - Actie: "Delete" knop

KERNFUNCTIES:
1. Map kiezen: Selecteer de map waar lokale llama.cpp builds staan
2. Scan: Detecteer builds (llama-server.exe, etc.)
3. Builds tonen: Naam, backend (Cuda, CPU, etc.), status, locatie
4. Build verwijderen: Delete knop per build
5. Nieuwe build toevoegen: (mogelijk via "Map kiezen" flow)

================================================================================
TECHNISCHE NOOT
================================================================================

Deze app is een desktop applicatie (WPF/WinUI of vergelijkbaar) die:
- GGUF modellen scant en beheert
- llama.cpp builds (runtimes) detecteert en start
- Per-model startparameters kan definiëren en opslaan
- Modellen kan laden/unloaden via een lokale server (poort 8081)
- Live runtime logs toont
- UI met Dutch (Nederlandse) tekst

De architechtuur suggereert:
- Modelmanager: scant mappen, toont GGUF bestanden
- RuntimeManager: detecteert llama.cpp builds
- ProfileManager: slaat startinstellingen per model op
- ServerController: start/stopt llama-server.exe met juiste parameters
- LogViewer: toont realtime server-logs
